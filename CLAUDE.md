# CLAUDE.md

PhyML: maximum-likelihood phylogenetics in C (about 130,000 lines), plus the
Bayesian tools PhyTime (dating) and PhyREX (spatial coalescent) built from the
same sources. `PHYML_REPORT.md` holds a full assessment of the code and its
known bugs.

## Build

```sh
sh ./autogen.sh && ./configure --enable-phyml && make   # binary: src/phyml
```

- One binary per configure run, chosen by a macro: `--enable-phyml`,
  `--enable-phytime`, `--enable-phyrex`, `--enable-phyml-mpi` (uses `mpicc`
  and `mpi_boot.c`), and others. Sources are listed in `src/Makefile.am`.
- OpenMP (`--threads`) is enabled by `AC_OPENMP` when the compiler supports
  it (`--disable-openmp` turns it off). Apple clang needs Homebrew `libomp`:
  `CPPFLAGS="-Xpreprocessor -fopenmp -I$(brew --prefix libomp)/include"
  LIBS="-L$(brew --prefix libomp)/lib -lomp"`.
- `configure` always adds `-march=native`. On x86-64, `src/sse.c` does not
  compile without SSE3, so builds by hand need `-march=native` or `-msse3`.
- `config.h`, `config.log`, `config.status`, the generated `Makefile`s and
  the LaTeX outputs in `doc/` are tracked in git, and `config.h` is stale. Do
  not include their churn in commits unless asked.

## Tests

CI runs the suite: `.github/workflows/tests.yaml` (`check` on Linux x86-64,
Linux ARM64 and macOS ARM64, `check-mpi`, weekly `check-asan`) and
`.gitlab-ci.yml` (autotools build, `check` and `check-mpi` on Debian x86-64,
ARM64 when `ARM64_RUNNER_TAG` is set, `check-asan` on schedule).

```sh
make -C test check        # unit (C) + functional (Python) tests, 1-2.5 minutes
make -C test check-mpi    # needs mpicc/mpirun; Open MPI: MPIRUN="mpirun --oversubscribe"
make -C test check-asan   # whole functional suite on the sanitizer build (slow)
```

- `test/Makefile` builds its own binaries from `src/` into `test/build/`
  (normal, scalar `-DDISABLE_NATIVE`, ASan+UBSan, `-DNDEBUG`, OpenMP),
  without autotools. Python tests use only the standard library.
- `test/functional/oracle.py` is an independent likelihood implementation.
  Fixed-parameter likelihoods (`-o n`) must match it to 1e-8, so changes to
  models or the likelihood engine are checked there.
- Searches and bootstraps use `rand()`, which differs between C libraries.
  Tests check properties (true topology recovered, optimality, ranges), not
  exact values; keep new tests that way. Comparing two runs of one binary
  exactly is fine, but pass `--r_seed`: the default seed comes from the clock.
- `test_threads.py` requires outputs to be identical for any `--threads`.
- Known bugs are tests marked `known_bug(...)` (Python) or `KNOWN_BUG(...)`
  (C), reported as expected failures. When you fix one, its test reports an
  unexpected pass and the run fails: remove the marker in the same change.
  `PHYML_SHOW_KNOWN_BUGS=1` runs them as ordinary tests to show how they fail.
- Test data in `test/data/` is generated by `make -C test data`
  (`test/tools/make_data.py`, deterministic).
- See `test/README.md` for the layout and the list of known bugs.

## Code map (`src/`)

| File | Role |
| --- | --- |
| `main.c` | `main()` for each program, selected by `PHYML`, `PHYTIME`, ... |
| `cl.c`, `interface.c`, `help.c` | Command line, PHYLIP-style menu, help text |
| `io.c`, `nexus.c`, `xml.c` | Alignment, Newick, NEXUS and XML input; output files |
| `lk.c`, `sse.c`, `avx.c`, `eigen.c`, `models.c` | Likelihood engine and substitution models |
| `optimiz.c` | Branch-length and parameter optimisation |
| `spr.c`, `pars.c`, `bionj.c` | Tree search, parsimony, BioNJ |
| `alrt.c`, `tbe.c`, `mpi_boot.c` | Branch supports (aLRT, aBayes, SH), TBE, MPI bootstrap |
| `sms.c` | SMS model selection (`--sms`), run from `main()` before the analysis |
| `structure.c` | Structure models of Le & Gascuel 2010 (`-m EX\|EHO\|EX_EHO`, `--struct_model`, `--struct_file`) |
| `lg4.c` | LG4M and LG4X (Le, Dang & Gascuel 2012): one matrix per rate category |
| `utilities.c/.h` | Core structs (`t_tree`, `t_node`, `t_edge`, `t_mod`, `option`), bootstrap, bipartitions, everything else |
| `mixt.c` | Mixture and partition models (XML) |
| `times.c`, `rates.c`, `mcmc.c`, `phyrex.c`, ... | PhyTime and PhyREX |

## Conventions and gotchas

- Allocate with `mCalloc` and free with `Free`; errors go through `Exit`,
  `Warn_And_Exit` or `assert`, which end the process (there is no error
  return path).
- Never put side effects inside `assert()`: `io.c:1504` does, and `-DNDEBUG`
  builds then hang.
- Fixed-size buffers: `T_MAX_FILE` (200), `T_MAX_NAME` (1000), `T_MAX_LINE`
  (2 MB). Bound every copy into them.
- `-t` is kappa (rate ratio), not the ts/tv ratio the help text describes.
- Bootstrap replicates share `s_opt`, `io` and likelihood buffers with the
  main tree; writing to them during a replicate changes the main analysis.
- Multithreading is OpenMP over site patterns in the likelihood loops
  (`Lk`, `dLk`, `*Update_Partial_Lk*`, `*Update_Eigen_Lr`), sized by
  `Lk_Site_Threads()` (`io->n_threads`, at least 128 patterns per thread). In
  those loops, write only the current site's entries and use per-thread
  scratch: the `*_Site` variants (`Lk_Core_Site`, `Pull_Scaling_Factors_Site`)
  take scratch vectors instead of `tree->site_lk_cat`, `b->sum_scale_*_cat`
  and `tree->curr_site`. Sums over sites are done afterwards in site order,
  so results do not depend on the number of threads. Mixture models (`mixt.c`)
  still run serially.
- SMS (`sms.c`) fits each candidate model in-process on a fixed tree, like
  a `phyml -o lr -u tree --r_seed N` run of the SMS 2.1.1 scripts: it swaps
  `io->mod` for the candidate (some routines read `io->mod`), reseeds `rand()`
  before each fit, and writes the Step 1 tree as `main()` writes its tree
  file, so the fits match the scripts. Then it sets `io->mod` to the selected
  model; `SMS_Set_Parameters` starts the analysis from the SMS estimates.
  `-m`, `-f`, `-v`, `-a`, `-t`, `--freerates` and `--aa_rate_file` are refused
  with `--sms`.
- Structure models (`structure.c`, `mod->smod`) turn each class matrix (plus
  LG for CONF/LG) times each Gamma category into one rate category with its
  own eigen system (`STRUCT_PMat`) and site-specific weights (`STRUCT_Weight`,
  read in `Lk_Core_Site`). Site classes are per pattern, so annotations are
  read before `Compact_Data` and columns are not merged across classes
  (`io->colalias = NO`). Branch lengths are optimised with Brent, and output
  trees are multiplied by the mean rate (`STRUCT_Mean_Rate_Data`). Rates,
  class proportions and starting values (chi = 0.8) follow the authors'
  PhyML-Structure binary, which gives the same likelihoods to 2e-3.
- Models with one matrix per rate category (structure models, LG4M and LG4X,
  `mod->lg4`) are read through `Cat_Eigen` and `Cat_Pi` (`models.c`): use
  them, not `mod->eigen` or `mod->e_frq->pi`, in likelihood code. LG4M and
  LG4X reuse the Gamma and FreeRate code for the rates and weights; LG4X
  first fits LG4M (`main.c`), as in the paper.
- New built-in protein matrices go in `init.c` (`Init_Qmat_*`, or a PAML
  lower triangle via `Init_Qmat_Lower_Triangle`), `Init_Model`,
  `Set_Model_Name`, the `-m` parser and the `-d nt` reset list in `cl.c`, and
  `help.c`. Add the PAML file to `test/data/aa_matrices/` for the oracle test.
- Match the surrounding style: `Capitalised_Function_Names`, `phydbl` for
  floating point, 2-space indentation.
